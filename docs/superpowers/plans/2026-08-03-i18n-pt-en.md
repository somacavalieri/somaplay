# Interface em dois idiomas (PT/EN) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Dar ao app um seletor PT/EN que troca a interface inteira, mais um ajuste independente de notação de acordes (brasileira ↔ internacional).

**Architecture:** Um módulo `i18n.js` sem estado externo expõe `t(key, params)` e lê o idioma de uma variável de módulo. Como `update()` reconstrói `app.innerHTML` a cada render, trocar idioma é `setLang() → saveSettings() → update()` — sem observadores nem binding. As strings vivem em dois mapas planos (`i18n/pt.js`, `i18n/en.js`) guardados por um teste de paridade de chaves. A notação de acordes é um módulo puro separado, aplicado só ao que o app produz.

**Tech Stack:** JavaScript vanilla (ES modules, sem build), Node ≥ 20 para `node --test`, zero dependências de runtime.

**Spec:** [`2026-08-01-i18n-pt-en-design.md`](../specs/2026-08-01-i18n-pt-en-design.md)

## Global Constraints

- **Zero dependências de runtime.** Nada de npm install. ES modules servidos como estão.
- **Node ≥ 20**, testes com `node --test`, rodados de dentro de `app/`.
- **Todo módulo novo em `app/js/` precisa entrar no array `SHELL` de `app/sw.js`** — senão o app quebra offline. E **toda alteração do `SHELL` exige subir o `VERSION`** na linha 2 do mesmo arquivo, senão os clientes instalados seguem com a lista antiga.
- **Nunca renomear `DB_NAME` em `app/js/db.js`.** Apaga a biblioteca de todos os usuários.
- **Nunca converter a notação dentro da cifra do usuário.** Cifra em texto alinha acorde sobre letra por coluna de caractere; `A7M` tem 3 caracteres e `Amaj7` tem 5. Ver §4.1 da spec.
- **Só a interface é traduzida.** Dados do usuário — títulos, artistas, estilos, letras, cifras, nomes de lista — nunca.
- **Português é a fonte da verdade** das strings. O inglês segue o tom do `README.md`.
- **Não commitar conteúdo musical de terceiros** (cifras, letras, áudio).
- Chaves de tradução são **planas e namespaced por tela**: `settings.backup.export`, `home.tabs.artists`.
- `localeCompare(..., 'pt')` em `state.js:107` ordena nomes de artista e **fica como está** — é ordenação de conteúdo em português, não de interface.

- [ ] **Step 4: Implementar o módulo**

Criar `app/js/i18n.js`:

```js
// i18n.js — tradução da interface. Sem dependências, testável em node --test.
import { PT } from './i18n/pt.js';
import { EN } from './i18n/en.js';

const TABLES = { pt: PT, en: EN };
let current = 'pt';

export function setLang(lang) {
  current = TABLES[lang] ? lang : 'pt';
  return current;
}

export function getLang() {
  return current;
}

// Recebe o idioma por parâmetro (não lê navigator) para poder ser testado em Node.
export function detectLang(navLang) {
  return String(navLang || '').toLowerCase().startsWith('pt') ? 'pt' : 'en';
}

export function t(key, params) {
  const table = TABLES[current] || PT;
  let s = table[key];
  if (s === undefined) s = PT[key];       // fallback: português
  if (s === undefined) return key;        // fallback final: a própria chave
  if (params) {
    for (const k of Object.keys(params)) {
      s = s.split(`{${k}}`).join(String(params[k]));
    }
  }
  return s;
}
```

**O procedimento, por arquivo:**

1. Localizar as strings visíveis:

```bash
cd app && grep -nP '>[^<>{}]*[A-Za-zÀ-ÿ][^<>{}]*<' js/render/<arquivo>.js
grep -n 'title="[^"]*"\|placeholder="[^"]*"\|aria-label="[^"]*"' js/render/<arquivo>.js
```

2. Para cada string encontrada, acrescentar a chave a **`i18n/pt.js` e `i18n/en.js`**, no namespace da tela.

- Nome de artista, título de música, estilo, nome de lista, letra, texto de cifra

- O nome dos idiomas no seletor ("Português", "English")

```js
// chord-notation.js — converte a grafia do acorde entre a convenção brasileira
// e a internacional. Puro, sem estado.
//
// IMPORTANTE: nunca aplicar à cifra em texto do usuário. A cifra alinha acordes
// sobre a letra por coluna de caractere, e os nomes têm larguras diferentes
// ('A7M' = 3, 'Amaj7' = 5). Ver §4.1 da spec de i18n.

// brasileiro → internacional. Várias grafias brasileiras caem no mesmo destino:
// '(5-)' e '(b5)' são o mesmo acorde, por isso NÃO existe identidade estrita de
// ida e volta — a propriedade que vale é a estabilidade da forma canônica.
const TO_INTL = {
  '(b13)': 'b13', '(13-)': 'b13',
  '(b5)': 'b5', '(5-)': 'b5', '5-': 'b5',
  '(b9)': 'b9', '(9-)': 'b9',
  '(11)': '11', '(13)': '13', '(9)': '9',
  '(4)': 'sus4',
  '7M': 'maj7',
  '°': 'dim',
};

// internacional → brasileiro (forma canônica de cada destino)
const TO_BR = {
  maj7: '7M', sus4: '(4)', dim: '°',
  b13: '(b13)', b5: '(b5)', b9: '(b9)',
  11: '(11)', 13: '(13)', 9: '(9)',
};

// Uma passada só, alternativas mais longas primeiro. Passada única importa: com
// substituições sequenciais, o resultado de uma vira entrada da seguinte e o
// nome se corrompe.
const RE_BR = /\(b13\)|\(13-\)|\(b5\)|\(5-\)|\(b9\)|\(9-\)|\(11\)|\(13\)|\(9\)|\(4\)|7M|5-|°/g;

// No sentido inverso os números soltos (9/11/13) só valem no FIM do nome. Sem a
// âncora, o '9' de 'C7(9-)' — que já é brasileiro — viraria 'C7((9)-)'.
const RE_INTL = /maj7|sus4|dim|b13|b5|b9|(?:11|13|9)$/g;

// A parte antes de '/' é o acorde; depois de '/' é o baixo e nunca muda.
function onBody(name, fn) {
  const s = String(name);
  const i = s.indexOf('/');
  if (i === -1) return fn(s);
  return fn(s.slice(0, i)) + s.slice(i);
}

export function toIntl(name) {
  return onBody(name, (body) => body.replace(RE_BR, (m) => TO_INTL[m]));
}

export function toBr(name) {
  return onBody(name, (body) => body.replace(RE_INTL, (m) => TO_BR[m]));
}

export function display(name, notation) {
  return notation === 'intl' ? toIntl(name) : toBr(name);
}
```
